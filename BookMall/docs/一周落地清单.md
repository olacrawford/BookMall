# 一周落地清单

这份清单按“低基础、能落地、简历优先”设计。每完成一项，就把它对应的简历句子和面试素材写到 `docs/stages/.../PIKE.md`。

## 使用方式

- 每天先花 15 分钟读 [AI学习地图](./AI学习地图.md) 对应概念
- 不要一天理解太多概念
- 每项都有“完成标志”，到了就算过，不用追求完美

## Day 0：熟悉项目和学习方向

目标：知道原有系统长什么样，知道改造后加什么。

任务：

- [ ] 读 [改造后 README](./README-改造后.md)
- [ ] 读 [可行性评估](./可行性评估.md)
- [ ] 读 [阶段实施方案](./阶段实施方案.md)
- [ ] 读 [AI学习地图](./AI学习地图.md)
- [ ] 跑通一次现有 BookMall 后端/前端，或至少能启动一个服务
- [ ] 能画出：用户 -> Gateway -> Auth/Order/Payment -> MySQL/MQ/Redis

完成标志：

- 能说清 5 个概念：LLM、Tool Calling、Agent、RAG、MCP
- 知道项目不是“AI 客服”，而是“AI 建议 + 系统执行 + 工单流程”

## Day 1：Stage 01 领域建模

可以先不写业务代码，但必须完成设计。

任务：

- [ ] 设计售后相关表字段
- [ ] 设计售后状态机
- [ ] 设计规则版本和审批策略
- [ ] 写出第一份 PIKE 文档
- [ ] 在 [简历与面试](./简历与面试.md) 里记录“状态机”简历句

需要理解的概念：

- 状态机
- 规则版本
- Human In The Loop

完成标志：

- 能回答：为什么状态不能随便跳？
- 能回答：为什么工单要绑定规则版本？

## Day 2-3：Stage 02 售后业务域

目标：`bookmall-after-sale` 可启动，核心服务有单元测试。

任务：

- [ ] 建表 SQL
- [ ] 实体、Mapper、Service、Controller
- [ ] 售后状态机服务
- [ ] 策略引擎初版
- [ ] 工作流表和推进逻辑
- [ ] 退款幂等
- [ ] 审计写入
- [ ] 输出 CHANGELOG / THOUGHT / PIKE

需要理解的概念：

- 状态机
- 工作流
- 幂等
- 审计

完成标志：

- 后端能启动
- 能通过单元测试说明“重复退款只执行一次”
- 能说出工作流每步为什么落库

## Day 3-4：Stage 03 AI 决策域

目标：AI 根据工单内容产出结构化 Decision，并附带证据。

任务：

- [ ] 设计 `TicketContext` 和 `Decision` JSON Schema
- [ ] Mock LLM
- [ ] Agent 简单循环
- [ ] MCP 工具白名单
- [ ] 订单/物流/风控/规则工具
- [ ] MySQL 版 RAG 规则召回
- [ ] 把证据、规则版本、成本记录落库

需要理解的概念：

- Tool Calling
- Agent
- MCP
- RAG

完成标志：

- 同一个工单能稳定得到同一类 Decision
- 能回答：MCP 工具为什么不能包含退款工具？
- 能回答：RAG 证据从哪里来？

## Day 4-5：Stage 04 端到端闭环

目标：浏览器里能跑通两条路径。

任务：

- [ ] 用户提交售后页面
- [ ] 工单详情页
- [ ] AI 分析和证据展示
- [ ] 自动退款路径
- [ ] 人工审批路径
- [ ] 审批页
- [ ] 审计查询页

需要理解的概念：

- Workflow
- Human In The Loop
- 前端如何展示 AI 结果

完成标志：

- 能演示“低金额自动处理”
- 能演示“高金额人工审批”
- 用户看不到别人的工单

## Day 6：Stage 05 可靠性与验收

目标：把失败场景补上，而不是只演示成功路径。

任务：

- [ ] 重复提交售后测试
- [ ] 重复退款测试
- [ ] 消息重复消费测试
- [ ] 流程中断恢复
- [ ] AI JSON 解析失败处理
- [ ] 审计链路完整
- [ ] 整理 3-4 个简历点

需要理解的概念：

- 幂等
- Outbox
- 消息队列
- Trace/审计

完成标志：

- 能演示或测试：重复请求不会重复退款
- 能说明：流程中断后如何恢复
- 能写完 [简历与面试](./简历与面试.md) 里的四个简历点

## Day 7：面试准备与演示

目标：不是继续加功能，而是把项目变成能面试的项目。

任务：

- [ ] 录制 3 分钟演示或写演示脚本
- [ ] 按 [简历与面试](./简历与面试.md) 写最终简历
- [ ] 过一遍 20 个高频面试题
- [ ] 模拟讲 60 秒项目介绍
- [ ] 至少手写一次状态机、幂等判断、审批恢复逻辑

完成标志：

- 能把整条链路讲顺
- 能被连续追问 10 个问题而不崩
- 手写核心逻辑时不依赖 AI

## 每周结束必查

- [ ] 后台能编译
- [ ] 演示路径能跑
- [ ] 每个阶段有 PIKE
- [ ] S级手写点确实是自己写的
- [ ] 简历上有 3-4 个可能被追问的点
- [ ] 面试问题集里每个点都有答案
