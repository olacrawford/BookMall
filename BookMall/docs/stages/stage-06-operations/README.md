# Stage 06 运营端增强执行手册

## 本阶段目标

从“用户能提交、能退款”升级到“运营人员能工作”。

完成后你能：

- 查看工单队列
- 快速定位待审批任务
- 查看 AI 证据
- 查询审计
- 区分用户和运营角色权限

## 前置依赖

- 第一周 Stage 01-05 已完成
- 已理解现有 Auth 与 Gateway JWT 透传

## 要做的事

- [ ] 1. 增加用户角色字段或角色表，初始化客服/审批人/风控账号。
- [ ] 2. 在 `bookmall-after-sale` 增加运营端接口：
      - `GET /after-sales/queue`
      - `GET /after-sales/{id}/analysis`
      - `GET /approval-tasks?status=WAITING`
      - `GET /audits?userId=&action=&startTime=&endTime=`
- [ ] 3. 在网关或者运营端服务增加角色校验，普通用户不能访问运营接口。
- [ ] 4. 前端增加运营工作台：
      - 工单队列页
      - 审批工作台
      - 审计查询页
      - 工单详情中展示 AI 决策、证据、风险
- [ ] 5. 给关键列表加索引：
      - 工单状态/创建时间
      - 审批任务状态/审批人/创建时间
      - 审计用户/动作/时间
- [ ] 6. 增加 `trace_id`：
      - 网关生成
      - 服务日志打印
      - 审计、AI 调用、工具调用共享
- [ ] 7. 增加基础指标/可观测性：
      - 待审批数量
      - 自动处理数量
      - 失败工单数
      - LLM 调用耗时
- [ ] 8. 写权限测试和页面验收。
- [ ] 9. 更新 CHANGELOG / THOUGHT / PIKE。

## S级手写点

- 运营权限边界
- 审计查询范围和越权校验
- 审批任务分配

## 验收清单

- [ ] 普通用户调用运营接口返回 403 或业务拒绝
- [ ] 运营人员能看所有工单
- [ ] 普通用户只能看自己的工单
- [ ] 审批工作台能通过/驳回
- [ ] 审计查询能按用户/动作/时间过滤
- [ ] 日志和审计有 `trace_id`
- [ ] 页面展示待审批数量等关键指标

## 面试沉淀

简历候选：

```text
增加运营工单队列、审批工作台与审计查询，按用户/运营/审批角色隔离权限，以 trace_id 串起 AI 调用、业务执行和审计记录。
```

面试问题：

1. 运营和用户如何区分？

   回答重点：认证仍是 JWT，RBAC 控制接口；普通用户不能访问运营路由。

2. 审计有什么用？

   回答重点：任何 AI 建议、审批、退款都能追到操作者、决策和证据。
