# 阶段文档标准

这份标准决定阶段文档是否合格。目标是：

> 任何一个阶段，学习者只看本阶段文件夹里的文档，就能独立完成、验收，并沉淀出面试素材。

## 每个阶段文件夹必须包含

```text
docs/stages/stage-{序号}-{名称}/
  README.md   # 执行手册：目标、任务、步骤、产出、验收、面试沉淀
  PIKE.md     # 阶段复盘：Problem / Insight / Key Decisions / Evidence
```

## README.md 必须写清

| 段落 | 要求 |
| --- | --- |
| 本阶段目标 | 一句话说清完成后得到什么 |
| 前置依赖 | 必须完成哪些前面阶段 |
| 学习概念 | 先读哪些概念，理解到什么程度 |
| 要做的任务 | 按顺序编号，每项是一个动作，不是形容词 |
| 输出文件 | 明确新增/修改哪些代码、SQL、文档 |
| S级手写点 | 明确哪些必须自己写 |
| 验收清单 | 每项可验证，能通过测试、命令或页面确认 |
| 面试沉淀 | 每项更新简历候选句、面试问题和回答 |
| 完成后下一步 | 明确进入哪个阶段文件夹 |

## PIKE.md 必须写清

| 字母 | 含义 | 内容标准 |
| --- | --- | --- |
| P | Problem | 本阶段要解决什么业务/工程问题，卡在哪里 |
| I | Insight | 痛点、难点、我们的思考，为什么这么选 |
| K | Key Decisions | 候选方案、确定方案、替代方案、影响 |
| E | Evidence | 测试结果、演示路径、产出文件、面试可讲点 |

禁止只写“实现了 xx”，必须写“为什么这样做”。

## 验收清单标准

每条验收标准必须满足：

- 可以用命令、页面、测试用例验证
- 明确“通过”表现是什么
- 不通过时知道改哪里
- 有可以直接写进简历的产出

## 面试沉淀标准

每个阶段结束至少新增：

- 一句简历候选话术
- 2 个面试问题
- 每个面试问题的回答重点
- 1 个“面试官深挖时我会主动展示的失败场景”

## 不合格信号

- 只有概括，没有任务步骤
- 验收标准写“前端实现售后页”，但没说怎么算完成
- 没有面试沉淀
- PIKE 只有空标题
- 文档读了之后不知道下一步打开哪个文件

## 合格判定

- [ ] README 按顺序读一遍，能开始第一项任务
- [ ] 每项任务知道完成后长什么样
- [ ] 验收清单自己能执行
- [ ] 面试素材能直接用于简历和口述
- [ ] PIKE 记录了真实取舍和失败处理
