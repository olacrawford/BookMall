# AI 售后智能运营平台可行性评估

## 结论

可行，且建议按“70% 后端业务系统 + 30% AI”实施。

理由不是技术名词多，而是这个场景天然约束了 AI 的使用方式：

- 售后业务有明确状态机、金额、审批、退款、库存、订单联动
- AI 无法独立完成资金操作，必须有 Policy、Risk、Approval、Workflow
- 召回规则必须带证据，不能只输出一句话
- 流程中断必须恢复，退款必须幂等，审计必须可查

这些约束让项目天然成为“企业业务系统”，而不是“AI Demo”。

## 现状资产复用

| 现状能力 | 对本项目的价值 | 复用程度 |
| --- | --- | --- |
| 用户 + JWT + 网关透传 `X-User-Id` | 售后单归属、运营权限、越权控制 | 高 |
| 订单 + 订单明细 + 支付单 | 售后单关联订单、退款目标、金额快照 | 高 |
| 库存预占/确认/释放 | 售后重发/退货入库/赔付库存联动 | 中高 |
| RabbitMQ 支付事件 | 已经掌握事件驱动和幂等消费模式 | 高 |
| Redis 缓存 + Sentinel | 规则缓存、限流、防并发 | 中 |
| 前端登录/订单/支付链路 | 售后页面可复用用户态、请求封装和组件风格 | 高 |

## 可行性拆解

| 维度 | 判断 |
| --- | --- |
| 业务可行性 | 售后流程是电商真实高频场景，可以组织出完整工单、规则、审批、退款、审计闭环 |
| 技术可行性 | Java + Spring Boot + MySQL + Redis + RabbitMQ 足以支撑 MVP；AI 层可先用 Mock 或 OpenAI-compatible 接口 |
| 时间可行性 | 一周可完成核心闭环；不要在第一周做完整企业级，后续一个月逐步增强 |
| 数据可行性 | 无需真实业务数据；通过种子订单、Mock 物流、售后规则文档即可演示 |
| LLM 可用性 | 无 Key 时采用 Mock LLM，按固定 JSON Schema 返回决策；有 Key 时替换真实模型 |
| RAG 可行性 | 第一周用 MySQL 规则分块 + 关键词召回；一个月后再接向量库和评测集 |
| 面试差异化 | 能支撑状态机、规则引擎、工作流、幂等、审批、MCP、RAG 等多个可深挖问题 |

## 一周可行性边界

### 可以做到

- 售后单创建、AI 分析、规则命中、风险分级
- 低风险自动退款 / 中风险人工审批 / 高风险拒绝或转风控
- 退款记录、订单售后状态联动、审计日志
- MCP 工具契约与调用记录
- RAG 规则召回并展示条款证据
- 前端工单页 + 审批页 + 详情页

### 第一周不做

- 不接真实物流平台，使用 Mock 物流数据
- 不做完整多租户、复杂 RBAC
- 不追求高并发，先保证状态机和幂等正确
- 不接入完整 Prometheus/OpenTelemetry
- 不接完整向量数据库
- 不处理真实资金和支付渠道

这些不是缺陷，是阶段边界。后续一个月逐项增强。

## 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 第一周范围过大 | 无法闭环 | 只做一条主链路：投诉 -> 分析 -> 规则 -> 审批 -> 退款 -> 审计 |
| LLM 输出不稳定 | AI 决策不可靠 | 强制 JSON Schema + 校验器；Mock 模式保证演示 |
| 退款重复执行 | 资金/状态错误 | 幂等键 + 退款状态机 + Outbox/MQ 幂等消费 |
| 流程中断 | 工单卡死 | Workflow Step 持久化 + 重试次数 + 恢复扫描 |
| 经验不足导致核心手写不过 | 面试讲不清 | S级手写点集中在状态机、规则、工作流、幂等，AI 只做脚手架 |
| AI 项目又变成 CRUD | 亮点不足 | 坚持 AI 只建议、系统执行，每个阶段都必须验证“企业问题” |

## 简历价值判断

这一周闭环适合写成：

> 基于 Spring Cloud Alibaba 构建 AI 售后运营平台，实现投诉工单、AI 决策、规则引擎、人工审批、退款与订单状态联动的完整闭环；LLM 仅输出结构化建议，资金操作由 Policy + Workflow 强制执行，并通过幂等键和审计日志保证可重复、可追溯。

这个描述能引出面试问题：

- 为什么 AI 不能直接调用退款 Service？
- 状态机如何防止非法跳转？
- 规则版本变化后历史工单怎么处理？
- 退款和订单更新不是同一个事务怎么办？
- Agent 工具超时/失败怎么处理？
- RAG 如何证明答案有依据？

## 最终结论

建议按 `docs/阶段实施方案.md` 执行。第一周目标是在真实业务闭环上完成 3-4 个可深挖的简历点，不追求企业级完整度；第二周到一个月补强真实 AI、RAG、可观测性、运营端和面试交付。
