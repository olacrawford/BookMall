# EV-009 自动退款 / 人工审批端到端闭环

## 状态

`verified` / `simulation`

## 结论

低金额自动退款和高金额人工审批均能在本地完整走通；重复创建请求只产生一次退款副作用；普通用户无法访问审批队列。

## 环境

- macOS，Java 17，Spring Boot 3.2.5。
- MySQL 8.4、Nacos、RabbitMQ 本地可用。
- `bookmall-auth`（8060）、`bookmall-gateway`（8080）、`bookmall-order`（8050）、`bookmall-after-sale`（8093）单实例运行。
- A-C 通过 8093 携带 `X-User-Id` 验收；D 通过 8080 Gateway/JWT 完整 API 链路验收。
- 前置数据：`sql/updates/010_phase5_demo_seed.sql` 已执行。

## A. 低金额自动退款与幂等

命令（省略 curl 响应中的非关键字段）：

```bash
curl -X POST http://localhost:8093/after-sales \
  -H 'Content-Type: application/json' -H 'X-User-Id: 7' \
  -H 'Idempotency-Key: PH5-EVIDENCE-ARRAY-20260901-03' \
  -d '{"orderId":10001,"type":"LOGISTICS_NOT_RECEIVED",
       "description":"数组 evidence 与请求头幂等复验",
       "evidence":["驿站无包裹","门卫未签收"]}'
# 同 key 原样再执行一次
```

预期：同 key 两次返回同一个 `afterSaleId`，`t_refund_record` 只有 1 条。

实际：

```text
第一次：afterSaleId=1008，status=COMPLETED，policyAction=AUTO_REFUND
第二次：afterSaleId=1008，status=COMPLETED
t_refund_record after_sale_id=1008：1 条，status=SUCCESS，provider_ref=MOCK
t_after_sale_outbox：REFUND_EXECUTED-1008-RF... -> CONSUMED
t_audit_log：USER CREATE UNDER_REVIEW -> COMPLETED
```

## B. 高金额人工审批

```bash
curl -X POST http://localhost:8093/after-sales \
  -H 'Content-Type: application/json' -H 'X-User-Id: 7' \
  -H 'Idempotency-Key: PH5-HIGH-RECOVERY-20260901-02' \
  -d '{"orderId":10002,"type":"LOGISTICS_NOT_RECEIVED",
       "description":"高金额审批与流程恢复复验",
       "evidence":"高金额订单需要人工核实签收"}'

curl -X POST http://localhost:8093/approval-tasks/1004/approve \
  -H 'Content-Type: application/json' -H 'X-User-Id: 1' -H 'X-User-Roles: APPROVER' \
  -d '{"comment":"阶段 5 审批复验"}'
```

实际：

```text
创建：afterSaleId=1007，status=WAITING_APPROVAL，policyAction=REQUIRE_APPROVAL
审批：code=200，售后单 status=PROCESSING，审批任务 APPROVED
退款：http://localhost:8093/after-sales/1007/refund 返回 refund id=4，SUCCESS，199.00
最终：售后单 COMPLETED，workflow COMPLETED
```

## C. 普通用户权限

```bash
curl 'http://localhost:8093/approval-tasks?status=WAITING' -H 'X-User-Id: 7'
```

实际：`{"code":403,"message":"普通用户不能操作审批任务"}`。


## D. 通过 Gateway/JWT API

```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"ph5_user","password":"123456"}'

curl -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ph5_user","password":"123456"}'

TEST_TOKEN='Bearer <登录返回 token>' IDEMPOTENCY_KEY='PH5-GATEWAY-FINAL-20260901-06' \
  ./BookMall/docs/project-enhancement/scripts/verify-week-one.sh
# 脚本批准后再补：POST /api/after-sales/1010/refund
```

实际：

```text
低金额：afterSaleId=1009，COMPLETED，退款 39.80 一条；同幂等键重放返回同一 ID
高金额：afterSaleId=1010，WAITING_APPROVAL -> 任务 1005 APPROVED -> PROCESSING
退款：refund id=7，SUCCESS，199.00；最终 1010 COMPLETED，workflow COMPLETED，Outbox CONSUMED
AI：GET /api/after-sales/1009/analysis -> VALID，5 个工具结果，证据和规则命中
```
