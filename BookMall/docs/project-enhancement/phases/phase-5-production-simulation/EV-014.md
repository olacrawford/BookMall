# EV-014 AI 异步长链路最终一致性

## 状态

`verified` / `simulation`

## 结论

AI 分析、工具证据、审计、Outbox 和工作流恢复可关联到同一售后链路；最终状态在本地模拟中收敛，重复请求和恢复操作没有产生重复副作用。

## 环境

- 同阶段 5 本地环境；`bookmall-after-sale` 8093。
- 前置：低金额售后 `1008`、高金额售后 `1007` 已创建并完成相应业务路径。

## A. 持久化 AI 分析与证据

命令：

```bash
curl http://localhost:8093/after-sales/1003/analysis -H 'X-User-Id: 7'
```

实际：

```text
validationStatus=VALID
action=NEEDS_HUMAN
toolResults=5
evidenceIds=6
ruleHits=2
traceId=041693b5-804f-4d35-9dda-aa9c1b957c0a
```

DB 对照：

```text
t_ai_decision id=8，ticket_id=1003，VALID，mock-llm-phase4
t_tool_call_log：trace_id 041693b5...，5 条
t_ai_evidence：decision_id=8，6 条，含 ORDER/LOGISTICS/USER/RISK/POLICY
```

## B. Outbox 最终投递

对 `1007`、`1008` 的退款，`t_after_sale_outbox` 实际状态：

```text
REFUND_EXECUTED-1007-RF... -> CONSUMED
REFUND_EXECUTED-1008-RF... -> CONSUMED
retry_count=0
```

链路：退款事务写入 Outbox -> Worker 发布到 RabbitMQ -> 消费者按 `event_id` 幂等消费 -> 更新 `CONSUMED`。

## C. Worker 中断恢复

- step 30 `APPROVAL_APPROVED` 注入 `WORKER_INTERRUPTED`。
- `recover` 返回 1，`complete` 返回 true。
- 后续退款后 `1007` 和 workflow 均 `COMPLETED`。
- 详细记录见 `EV-010.md`。

## AI 特有记录

- provider/model：`mock` / `mock-llm-phase4`。
- prompt_version：`phase4-v1`。
- dataset_version：阶段 5 固定种子 `010_phase5_demo_seed.sql`。
- 工具调用：`query_order`、`query_logistics`、`query_delivery_proof`、`query_user_risk`、`query_after_sale_rule`。
- Token/成本：Mock 无真实计费；`latency_ms` 在 10-21ms 范围内，仅作本地参考。

## 限制

- Mock LLM 与本地关键词 RAG，不是真实 Provider/ES/Milvus。
- 单实例本地演示，不是跨库、集群或跨机房的一致性结论。
- “最终一致”只覆盖本地模拟中的重复请求、Outbox 投递和 Worker 中断恢复；真实支付渠道、真实消息积压和断链重连仍需后续演练。
