# EV-010 流程中断后可恢复

## 状态

`verified` / `simulation`

## 结论

高金额售后在审批后注入 `WORKER_INTERRUPTED`，失败步骤可从 `FAILED -> RETRYING -> COMPLETED` 恢复，业务继续执行退款并最终到达 `COMPLETED`。

## 环境

- 同一阶段 5 本地环境；`bookmall-after-sale` 8093。
- 前置：高金额售后 `1007` 已完成创建和审批，售后单状态 `PROCESSING`，workflow `RUNNING`，step 30 `APPROVAL_APPROVED`。

## 命令

```bash
curl -X POST 'http://localhost:8093/internal/workflow/steps/30/fail?errorCode=WORKER_INTERRUPTED&errorMessage=after-approval-worker-interrupted'
curl -X POST 'http://localhost:8093/internal/workflow/recover?limit=10'
curl -X POST 'http://localhost:8093/internal/workflow/steps/30/complete'
```

## 预期

- fail 后 step 30 = `FAILED`，记录错误码。
- recover 返回被恢复步骤数 > 0，step 30 = `RETRYING`。
- complete 返回 `true`，step 30 = `COMPLETED`，attempt_count 增加。

## 实际

```text
fail 响应：code=200
recover 响应：data=1
complete 响应：data=true
DB t_workflow_step id=30：
  status=COMPLETED
  attempt_count=2
  last_error_code=WORKER_INTERRUPTED
  last_error_message=after-approval-worker-interrupted
DB 售后单 1007：PROCESSING -> 随后退款 -> COMPLETED
DB workflow 7：REFUND_COMPLETED 后 status=COMPLETED
```

服务日志：

```text
workflow step marked failed stepId=30 errorCode=WORKER_INTERRUPTED
workflow step queued for retry stepId=30 attempt=2 nextRetryAt=...
workflow step recovery completed stepId=30
```

## 说明

中断恢复证明“checkpoint 可继续”，不代表系统自动替人工完成退款；本次恢复后仍由演示操作调用 `POST /after-sales/1007/refund` 才进入终态。

## 限制

- 使用内部故障注入接口模拟 Worker 中断，不是真实进程杀死的 OpenTelemetry/Trace 级演练。
- 单实例本地验证，未做跨实例抢占、延迟补偿或集群恢复测量。
