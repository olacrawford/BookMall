```text
t_after_sale_order

t_approval_task

t_audit_log

```

## 结论

- 售后单列表的 filesort 已消除，索引优化有真实 `EXPLAIN` 前后证据。
- 审批队列在 1000 行样本中新增 `create_time` 索引后仍选择全表扫描，按停止条件未保留索引。
- 审计 trace 已有索引，无需重复新增。
- HTTP 基线已执行：list 和 approval 在 5 并发、100 次请求下错误率均为 0%，P50/P95/P99、吞吐和资源占用见上文。

## 限制

- 本次同时有 MySQL EXPLAIN 和单实例 HTTP 基线；仍是本机 1000 行样本 + 5 并发规模，不是生产级高并发压力，也不应写成已优化的生产 P95。
- 索引优化只针对当前已知查询；新增 `user_id + status` 售后单查询时需要重新 EXPLAIN。
- 008 不可直接重复执行，脚本用于从 006 基线环境增量升级；回滚步骤见阶段 README。
