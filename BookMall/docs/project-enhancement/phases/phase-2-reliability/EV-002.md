## 覆盖点

- Outbox 同一事件消费两次只更新一次。
- `scanAndDispatch` 先发布 RabbitMQ 消息，再置 `DISPATCHED`。
- `AfterSaleOutboxPublisher` / `AfterSaleOutboxConsumer` 的序列化和消费入口通过单测。
- 工作流失败步骤恢复为 `RETRYING`，完成后工作流恢复 `RUNNING`。
- 物流 timeout/unavailable 注入后进入 `WAITING_HUMAN`，人工恢复后回到 `PROCESSING`。
- 普通用户访问他人售后单返回 403。
- 不含 `APPROVER` 角色的普通用户审批返回 403，带 `APPROVER` 角色可放行。
- Gateway 将 JWT `role` 透传为 `X-User-Roles`。
- Gateway Trace 过滤器编译通过。

## 限制

- 本证据是单测和编译级证据，不是真实 RabbitMQ 投递的端到端证据；尚未执行 Docker RabbitMQ 断链、重连和积压恢复演练。
- `DemoLogisticsQueryGateway` 是故障注入 adapter，不是真实物流服务。
- 旧 JWT 若没有 `role` claim，审批权限会回退到 `after-sale.approver-ids` 白名单，用户重新登录后新 token 才携带角色。
