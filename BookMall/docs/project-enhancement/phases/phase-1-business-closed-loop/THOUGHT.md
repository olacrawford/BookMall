# THOUGHT

阶段 1 的核心不是把接口堆出来，而是把售后链路拆成可控的业务对象：售后单、工单、流程、审批任务和退款记录各司其职。

今天最重要的判断有三点：

1. 售后单负责承载业务结果和状态机，工单负责承载沟通、决策和审计。
2. 规则判断必须先依赖订单快照和风险等级，再决定自动退款、人工审批还是风控复核。
3. 退款必须先查幂等，再推进状态，不能让一个接口同时承担“创建记录”和“状态收尾”而不做前置校验。

我没有把审批逻辑压进退款接口里，而是把审批任务单独暴露出来。这样可以保留人工节点，也能让自动路径和人工路径共享同一套状态机和审计模型。

实现时最需要警惕的是关联键混用。审批任务保存的是 `ticketId`，不是 `afterSaleId`；如果查错主键，表面上接口能返回，业务却会在审批/驳回时断掉。
