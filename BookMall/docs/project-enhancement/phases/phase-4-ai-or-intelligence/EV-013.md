## A. 独立 AI 中台调用

请求：

```bash
curl -X POST http://localhost:8093/internal/ai/analyze -H 'Content-Type: application/json' \
  -d '{"traceId":"PH4-INTERNAL-FIX-1788259239","ticketId":1003,"userId":7,"orderId":10001,
       "description":"包裹超过 3 天未揽收，请人工核实物流和签收证据","policyVersion":"v1",
       "userEvidence":["用户上传了物流停滞截图"]}'
```

预期：`code=200`，`validationStatus=VALID`，`action=NEEDS_HUMAN`，5 个工具成功。

实际：

- `intent=LOGISTICS_NOT_RECEIVED`
- `validationStatus=VALID`
- `t_tool_call_log` id 11-15，5 个工具全部 `success=1`。
- 证据包含 `order:10001`、`logistics:10001`、`delivery-proof:1003`、`risk:7`、`policy:v1#AFTER_SALE_LOGISTICS_NOT_RECEIVED#1`、`policy:v1#AFTER_SALE_DAMAGED#1`。

## B. 创建售后主链路

请求：

```bash
curl -X POST http://localhost:8093/after-sales \
  -H 'Content-Type: application/json' -H 'X-User-Id: 7' \
  -d '{"orderId":10001,"type":"LOGISTICS_NOT_RECEIVED","amount":39.80,"riskLevel":"HIGH",
       "evidence":"用户上传了物流停滞截图",
       "idempotencyKey":"PH4-MAIN-FIX-1788259246-4028"}'
```

预期：主链路在工单落库后调用 AI 分析，AI 只给建议，不触发自动退款；风险等级 HIGH 走人工风控。

实际响应：

```json
{"code":200,"message":"success",
 "data":{"afterSaleId":1002,"orderId":10001,"status":"RISK_REVIEW",
         "ticketId":1002,"decisionStatus":"AI_REVIEWED","policyAction":"RISK_CONTROL"}}
```

落库结果：

| 表 | 关键结果 |
| --- | --- |
| `t_after_sale_ticket` id 1002 | `decision_status=AI_REVIEWED` |
| `t_ai_decision` | id 6，`validation_status=VALID`，`model_name=mock-llm-phase4` |
| `t_tool_call_log` | id 16-20，5 个工具全部 `success=1` |
| `t_ai_evidence` | id 28-33，共 6 条证据，均带 `policy_version=v1` |
| `t_audit_log` | `AI_ANALYZE`（before NULL / after UNDER_REVIEW）与 `USER CREATE`（UNDER_REVIEW -> RISK_REVIEW） |

主链路没有把 AI 的 `NEEDS_HUMAN` 当成退出条件，也没有自动退款；状态仍由确定性 Risk 门控制。

## 过程中发现并修复的问题

现象：创建售后后 `decision_status=WAITING_HUMAN`，且 `t_tool_call_log` 无新记录，`t_audit_log` 出现 `AI_ANALYZE_FAILED`。

根因：`saveEvidence` 对两条来自不同文档但 `chunkNo=1` 的规则生成了相同 `policy:v1#1`，插入 `t_ai_evidence` 违反 `uk_ai_evidence`，导致 `analyze` 在工具日志落库前抛错。

修复：`RuleHit.evidenceId()` 改为 `policy:<version>#<documentCode>#<chunkNo>`，并新增 `RuleHitTest` 覆盖跨文档同块号场景。修复后上述 A、B 两条验收均通过。

## 限制

- 使用 `MockLlmClient`，未接真实 Provider。
- RAG 为 MySQL 关键词召回，非 ES/Milvus 向量检索。
- 单实例本地环境，未做双实例故障隔离测量（EV-011 仍是后续任务）。
- 本记录只证明「AI 建议 + 证据 + 审计」链路可用，不证明生产级模型准确率或高并发稳定性。
