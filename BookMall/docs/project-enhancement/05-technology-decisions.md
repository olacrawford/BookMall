# 技术决策与演进

版本优先沿用仓库锁定版本；新增依赖在编码前核对官方兼容性。下表是第一周决策，不是强制堆组件。

| 问题 | 候选 | 选择与理由 | 成本/风险 | 回滚 |
|---|---|---|---|---|
| 售后服务边界 | 新微服务；现有 order 扩展；模块化单体 | 逻辑独立服务，第一周可在一个模块内分包，减少 Feign/配置开销 | 新表和路由；后续拆分需契约 | 删除路由，保留表，停用入口 |
| AI Provider | Spring AI；OpenAI-compatible HTTP；Mock | `LlmClient` 接口 + 默认 Mock，保证无 Key 可运行；Provider 可替换 | Mock 不代表真实效果 | 切回 Mock 配置 |
| 工具协议 | MCP SDK；普通 HTTP；进程内接口 | 先做领域工具契约和白名单，内部实现可用 HTTP/进程内；MCP 是边界，不是写操作权限 | SDK 版本和协议适配风险 | 保留同一 `ToolRequest/Result` 接口 |
| RAG 存储 | 向量库；MySQL 分块关键词；Redis | 第一周 MySQL `rag_chunk` + 标签/关键词，环境少、易审计 | 语义召回有限 | 替换 `RagRetriever` 实现 |
| 流程 | 工作流引擎；自研 DB 驱动 | 5 个节点以内用持久化 Step + 恢复扫描，能解释状态和故障 | 复杂编排能力有限 | 后续适配引擎，事件契约不变 |
| 一致性 | 事务后直发 MQ；Outbox；分布式事务 | Outbox 与业务记录同事务，MQ 最终一致、消费者幂等 | 需要 Worker 和死信治理 | 暂停 Worker，人工重放 |
| 幂等 | Redis 锁；DB 唯一键；两者组合 | 资金/结果以 DB 唯一约束为最终屏障，Redis 只做短期去重 | 唯一键冲突需转业务结果 | 保留唯一索引，移除缓存 |
| 授权 | 仅网关；服务内 RBAC；完整 IAM | 网关认证 + 售后服务资源/角色二次校验 | 角色模型是增量工作 | 关闭运营入口，用户接口仍可用 |
| 观测 | 仅日志；Micrometer；完整 OTel | 第一周结构化日志/trace/audit，指标接口预留；完整 OTel 后续 | 指标暂不等于生产监控 | 日志字段兼容即可 |

## 不能接受的方案

- Agent 直接连 MySQL 或调用退款写接口。
- 用 Prompt 文本决定金额、审批或权限。
- 使用“当前规则”覆盖历史工单绑定的版本。
- 引入 Kafka、Kubernetes、向量数据库但没有一周内可重复的验证证据。
- 把 Mock LLM 的固定正确率写成真实模型效果。

## 资源预算

本地沿用 MySQL、Redis、RabbitMQ、Nacos Docker 资源；新增模块目标内存小于 512 MB，AI Mock 不需要 GPU/API Key。真实 Provider、向量库和监控的成本在一个月增强阶段重新评估。
