# 电商售后智能运营平台：唯一入口

> 从这里开始。其他文档都是本入口下面的专题、阶段或历史参考，不需要同时打开。

## 你现在要做什么

本项目只有一个目标：在 7 天内把遗留交易骨架重构成一条可演示、可测试、能支撑面试追问的电商售后主链路。

```mermaid
flowchart LR
  R[先看本页] --> CV[看简历目标]
  CV --> L[不会 AI？先看学习导览]
  L --> D[按阶段开工]
  D --> V[跑验收脚本并留证]
  V --> I[整理面试话术]
```

## 四个入口，按需选择

| 你的问题 | 唯一要打开的文件 | 看完做什么 |
|---|---|---|
| 简历最终写什么？ | [11-resume-first.md](./11-resume-first.md) | 把 4 条目标 bullet 拆成当天证据 |

## 七天只走这一条线

| 天 | 进入文件 | 当天必须留下的结果 |
|---|---|---|
| 第 1 天 | [阶段 0](./phases/phase-0-baseline.md) | 基线命令、旧链路图、售后状态草图 |
| 第 2-3 天 | [阶段 1](./phases/phase-1-business-closed-loop.md) | 表、接口、状态机、Policy、自动/审批分支 |
| 第 4 天 | [阶段 2](./phases/phase-2-reliability.md) | Outbox、幂等、超时、恢复、权限测试 |
| 第 5 天上午 | [阶段 3](./phases/phase-3-performance.md) | 固定负载、P95/P99、一个有依据的优化 |
| 第 5 天下午-第 6 天上午 | [阶段 4](./phases/phase-4-ai-or-intelligence.md) | Decision Schema、工具白名单、RAG 证据、Agent trace |
| 第 6 天下午-第 7 天 | [阶段 5](./phases/phase-5-production-simulation.md) | 自动退款/人工审批演示、故障记录、简历证据 |

阶段必须按顺序完成。当前阶段的验收门没过，不要跳到下一个阶段，也不要先接真实模型。

## 每个阶段收工前必须提交

在当前阶段目录补齐：

1. `THOUGHT.md`：今天理解了什么，AI 生成代码哪里需要人工改。
2. `PIKE.md`：一个真实问题、一个取舍、一个证据。
3. `CHANGELOG.md`：实际改了哪些文件、接口、表和配置。
4. `EV-*.md`：命令、输入、预期、实际、限制。
5. 一张面试卡片：一句简历话术 + 三层追问 + 一个失败场景。

没有证据的内容只能写“计划”，不能写进简历。

## 开工命令

```bash
docker compose -f docker-compose.infra.yml up -d
mvn -f BookMall/pom.xml -q test
# 完成接口后再执行：
TEST_TOKEN='Bearer <token>' ./BookMall/docs/project-enhancement/scripts/verify-week-one.sh
```

脚本输出的 JSON 放入 `evidence/`，再更新 [evidence-index.md](./evidence/evidence-index.md)。
